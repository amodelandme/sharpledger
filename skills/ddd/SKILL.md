# Domain-Driven Design for the ledger

Explain entities, value objects, aggregates, aggregate roots, services, and bounded contexts using ledger examples. Distinguish accounting principles from product policy. Choose boundaries by invariant and transactional needs; do not assume every pattern is necessary. Value objects must protect their invariants and money must use exact representations. Discuss focused aggregate repositories, application ports, and direct persistence approaches as alternatives; avoid generic wrappers without value. Domain events or a mediator are not automatic requirements.
