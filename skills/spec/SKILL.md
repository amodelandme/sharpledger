# Specify ledger features through guided discussion

Explain the business need and relevant accounting concepts before implementation. Ask one substantive question at a time, prioritizing decisions that affect behavior or guarantees; make routine assumptions explicit instead of turning every detail into a question. Define scope, examples, invariants, acceptance criteria, enforcement boundaries, transaction behavior, failure and concurrency scenarios, and verification. Capture a concise specification in the agreed project location when requested or needed, and obtain agreement on nontrivial behavior before implementation. Respect the current design-only phase and approved scope.
